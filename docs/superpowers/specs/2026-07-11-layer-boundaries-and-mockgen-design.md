# Layer Boundaries and Mockgen Design

## Goal

Clarify the composition root, keep infrastructure out of `internal/app`, and
make generated Uber mocks the only allowed test doubles. Local and CI linting
must execute the same Make target and pinned linter version.

## Layer boundaries

`internal/app` contains configuration loading only. It must not import pgx,
Postgres repositories, sqlc, HTTP adapters, or LLM adapters.

`cmd/api` is the composition root. It loads configuration, opens the Postgres
pool, creates Postgres infrastructure adapters, passes adapter-independent
dependencies to the HTTP adapter, and closes the pool during shutdown. It does
not contain domain rules, SQL, OpenAPI DTO conversion, or use-case behavior.

`internal/api/http` exposes only unauthenticated `/livez`. Docker Compose
already gates application startup on healthy Postgres and completed migrations,
so this owner-only deployment does not need a readiness endpoint or a database
health abstraction.

Domain and use-case packages retain the existing dependency rule: they do not
import HTTP, OpenAPI, Postgres, sqlc, or provider SDK types.

## Test doubles

Manual fake/stub implementations are prohibited in test code. The current
handwritten `fakeTx`, `fakeRow`, and executor implementations in Postgres
transaction tests are replaced with mocks generated by
`go.uber.org/mock/mockgen`.

The repository tracks the generated mocks and offers `make mocks` to regenerate
them using pinned `go.uber.org/mock/mockgen` v0.6.0. Test code uses `gomock.Controller`
and generated expectations. Generated mocks are the sole exception to the
handwritten-code comment rule, alongside existing OpenAPI and sqlc generated
files.

Production `StubClient` and OpenAPI 501 handlers are explicitly out of scope:
the no-fake/no-stub rule in this change applies to tests only.

## Lint parity

The Makefile pins the golangci-lint invocation to v2.12.2 and includes the
existing five-minute timeout. GitHub Actions runs `make lint`, rather than
duplicating a command. Therefore developers and CI run exactly the same linter
version, configuration, timeout, and invocation.

## Verification

Tests establish that `/readyz` is absent and transaction behavior is verified
through generated mocks. The complete
unit suite, tagged integration suite, build, `make lint`, and comment-boundary
scan run with Go 1.26. The integration suite continues to use an opt-in test
database only when `TEST_DATABASE_URL` is supplied.
